# Application interfaces and research opportunities

The entries below are proposed bridges grounded in the supplied corpus. They are integration directions, not new certifications. Shared arithmetic lemmas can be reused; domain-specific conclusions need domain-specific evidence.

| Domain | Reusable foundation | Next concrete bridge |
|---|---|---|
| NINE65 symmetric arithmetic | Exact quotient, projection, coefficient operations and costed readout | Map actual producers and consumers; verify no stored K, integer-only execution and correct authenticated coordinates; benchmark matching parameters |
| DSP and HCVlang scheduling | Typed lane operators and exact repeated state transitions | Specify signal encoding, scaling and saturation; test complete pipelines and schedule independence |
| Discrete numerical methods / NS | Exact arithmetic and compositional semantics | Prove the discretization's energy and consistency statements on its actual operators; establish analytic limits separately |
| Tropical / quantized computation | Integer piecewise-linear maps, winding and comparison queries | Implement an exact bounded max/sign consumer; separately measure encrypted cost and depth where encryption is used |
| Persistent data and distributed systems | Compatible observations, source/epoch binding and transition evidence | Specify crash/replay and transaction recovery; distinguish consistency detection from cryptographic authentication |
| Formal methods and compilers | Fiber criterion and semantic-preservation composition | Type observable requirements; reject a target query when the source observation does not determine it |
| Control and phase measurement | Adjacent/coupled observation readout | Establish physical observation authenticity, signed window and noise/error model before applying integer identities |
| Archeo-mathematics | Units, common measure, periodic coordination | Compare actual historical texts and artifacts with explicit modern constructions; preserve provenance and distinguish interpretation from historical verification |

A useful upstream consequence is a specification language for **what an operation must know**. A useful downstream consequence is sharing a proved observable interface across applications while allowing each machine profile its own representation and scheduling.
