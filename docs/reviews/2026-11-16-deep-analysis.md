## What the work says so far

### 1. One generates the finite scalar-compatible states

Start with the chosen unit and observe repeated addition through several moduli. The resulting coherent orbit has period `lcm(m₁,…,mₙ)`. Overlapping observations impose compatibility conditions. For example, moduli 6, 10 and 15 jointly distinguish 30 scalar classes, even though their raw Cartesian product contains 900 tuples. The manuscript gives a sound generalized-CRT argument; the included Lean package verifies important kernel/period components, rather than that entire orbit theorem.

This makes the difference between a scalar-compatible state and a general heterogeneous product state precise. A tuple can be a valid product state without being the result of one ordinary scalar operation.

### 2. Exactness depends on the requested output

If two admitted sources have identical observations, any answer computed only from those observations must agree for the two sources. Conversely, an output constant on every such group of indistinguishable sources factors through the observation image. Lean checks this general criterion.

This is useful beyond residue arithmetic: it is a specification for query interfaces, representation refinement and proof reuse. The existence theorem alone does not construct a fast decoder; the ring and integer modules provide concrete readouts for their stated settings.

### 3. Winding is an observable derived from qualified evidence

For `M > 0`, `A = M+1`, and authentic `r = X mod M`, `s = X mod A`, Lean verifies

```text
(r - s) mod A = (X / M) mod A
```

for signed integer X using Euclidean division. For `M=36`, `X=1000`, the readings are `(28,1)` and the result is `27`. If the admitted source range is `[0,1332)`, this is the exact quotient. The source `2332` has the same readings but quotient `64`; both quotients are `27 mod 37`. An actual range invariant supplies the distinction needed for exact integer recovery.

The runtime state in the concrete Lean core has just `main` and `anchor`. It derives K when comparison needs it. Its division outputs quotient and remainder as residue states; it does not maintain a scalar winding field or call a full-source reconstruction routine. Proof variables and ordinary test-oracle integers do not become runtime fields.

### 4. An output can need less than complete magnitude

For target modulus q, the required quotient distinction is only `K mod (q/gcd(M,q))`, together with the reference remainder. The target criteria and direct projection formulas formalize when the evidence already suffices. The architectural opportunity is to compute only the requested observable and avoid unnecessary full-value intermediates. Deriving and discarding an exact K changes storage and data flow; it does not make `(r,K)` contain less information than X.

### 5. Shared factors require a precise division contract

Failure of a modular reciprocal does not rule out ordinary quotient/remainder. The concrete bounded divmod proof accepts every positive admitted divisor, including divisors sharing factors with M or A. It accomplishes that using repeated subtraction and proved comparison.

A nonunit *observer anchor* is a different case. Standalone formulas prove reduced-resolution readout with certificates, while the executable `Frame` requires an inverse of M modulo A. The manuscript also proves stronger witness/valuation statements whose complete named formal counterparts remain to be added.

### 6. Reversibility and composition belong to particular operations

The written results identify which data an inverse needs: for example, quotient and remainder together retain an integer division input, whereas quotient alone generally does not. Exact operations compose when their value equations and successive admission conditions hold. Lean checks a homogeneous finite-program version and the concrete arithmetic loops. The full heterogeneous, partial-operation framework remains an explicit next formal target.

### 7. Refinement has a mathematical and an executable meaning

The manuscript's profinite argument correctly distinguishes ordinary integers from the larger space of all compatible finite observations. Its idempotent example establishes that the completion contains additional states. This section is a written mathematical proof, not an implemented refinement engine or a Lean topology development. An executable growing representation still needs a producer for each new authentic observation and a resource model.

## Reading and reproduction

Useful terms: **shell/main** is the primary modulus/readout; **anchor** is a coordinated additional observation; **winding K** is the Euclidean quotient relative to that shell; **admitted window** is the independently established domain selecting a representative; **fiber** is the set of sources sharing an observation; **scalar-compatible** means the readings can come from one scalar; **heterogeneous product state** carries lane-specific meaning. S6 and the manuscript's B6 denote the same six-prime set `{2,3,5,7,11,13}` here; S8 is a separate eight-prime profile.
